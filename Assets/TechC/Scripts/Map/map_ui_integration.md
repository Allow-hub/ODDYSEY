# Map UI Integration Notes

## Work scene

- Work scene: `Assets/TechC/Scenes/WorkScene/WorkScene_SR_Map.unity`
- Preview initializer: `MapPreviewBootstrap`
- Source UI prefab: `Assets/TechC/Prefabs/Map/Map.prefab`
- Preview data: `Assets/TechC/Data/Map/StageMapData.asset`

Open the work scene and enter Play Mode. `MapPreviewBootstrap` calls `MapController.Initialize` with the assigned `StageMapData`.
Change `currentNodeIndex` on `MapPreviewBootstrap` to preview cleared/current/locked states.
`MapController` rebuilds the visible node views from `StageMapData.nodes`, so data changes are reflected at runtime without manually matching the visible node count.

## Runtime entry point

The real game flow is:

1. `MainManager.EnterMap`
2. Instantiate `mapPrefab`
3. Subscribe to `MapController` events
4. Call `MapController.Initialize(currentStageMapData, mapProgress)`

So the production integration target is `Assets/TechC/Prefabs/Map/Map.prefab`.
Designer layout changes should be made on this prefab after the work-scene layout is approved.

## Intended UI state mapping

Based on the current design direction:

- Default or future node: tile `None`
- Cleared node: tile `Off`, icon hidden
- Selectable next node: tile matching its `nodeType` / event type, icon visible
- Player current position: character marker layered above the current node
- Player marker's bottom edge is placed slightly below the current node center
- Branch columns are calculated from `StageNodeData.nextNodeIndices`
- Single-node columns use `Y = 0`
- Multi-node columns are centered around the normal baseline, with adjacent nodes separated by `nodeGap.y`

Available map assets are under `Assets/TechC/Images/Maps`.

## Implementation policy

Selection uses bottom-screen `Choice.prefab` buttons generated by `MapController`.
Map nodes themselves are visual feedback only:

- `StageNodeData.nodeType` defines the visual/encounter type of that node
- `StageNodeData.nextNodeIndices` defines which map nodes are selectable from that node
- `MapProgressState.currentNodeIndex` marks the player's current node
- `Map.prefab` keeps one hidden `NodeView_Template` under `MapScrollView/Node`
- `MapController` instantiates visible `NodeView` objects from that template until they match `StageMapData.nodes.Count`
- `MapController` passes `Current` to the current node and `Active` to the selectable next nodes
- `MapNodeView` switches tile/icon/current-marker visibility from that state
- Future/locked `None` nodes still show their node-type icon
- The player marker's bottom edge is aligned slightly below the current node center, so the standing art appears to stand on the node
- `Choice.prefab` is instantiated under `choiceButtonContainer`
- `Choice.prefab` is a control button background plus node-type text; it does not reuse the map node tile/icon visuals
- Choice buttons are arranged horizontally under `choiceButtonContainer`
- If `choiceButtonContainer` is not assigned, `MapController` creates a temporary bottom-center horizontal container at runtime
- `NodeView` instances are placed inside the node content RectTransform
- `Map.prefab` should keep a permanent horizontal `ScrollRect` named `MapScrollView`
- If `mapScrollRect` is not assigned, `MapController` can still wrap the existing node content in a runtime `MapScrollView` as a compatibility fallback
- After refreshing the view, `MapController` centers the current node in the scroll viewport when possible
- `animateCurrentNodeScroll` and `currentNodeScrollDuration` control whether centering scrolls smoothly

## Map viewport tuning

There are two ways to tune the visible map area:

- Preferred setup: keep a `ScrollRect` object in `Map.prefab`, assign it to `MapController.mapScrollRect`, and edit that viewport RectTransform size directly.
- Fallback setup: leave `mapScrollRect` unassigned and edit `MapController.mapViewportSize`; the runtime `MapScrollView` uses this as its visible area size.

For the current horizontal layout, increasing `mapViewportSize.x` shows more columns at once, and increasing `mapViewportSize.y` gives more room for vertically branched nodes.

Use `Tools/TechC/Map/Configure Map Prefab` after large prefab edits to restore the expected `MapScrollView`, `Node` content, and centered current-marker layout.
